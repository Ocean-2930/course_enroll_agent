# 사업자·수강생 화면 안내와 이용 흐름

> 이 문서는 실제 사용자가 만나는 두 화면, **사업자 대시보드(`frontend/pages/dashboard.html`)** 와
> **회원 포털(`frontend/pages/member.html`)** 이 각각 무엇을 제공하고 어떤 순서로 쓰이는지 설명한다.
> 파일 구조·API 계약·DB 스키마는 [PROJECT_STRUCTURE.md](PROJECT_STRUCTURE.md)를 본다.
> 화면 구성이나 흐름이 바뀌면 같은 변경에서 이 문서도 갱신한다.

## 0. 두 화면 한눈에 보기

| | 사업자 대시보드 | 회원 포털 |
|---|---|---|
| 파일 | `pages/dashboard.html` | `pages/member.html` |
| 홈 진입 카드 | 📊 사업자 대시보드 | 🙋 회원 포털 |
| 대상 선택 | 상단에서 **아카데미** 선택(브라우저에 기억됨) | 첫 진입 시 **아카데미 → 회원** 선택 후 URL에 기록 |
| 보는 범위 | 그 아카데미의 **모든 회원** | **본인 한 명** |
| 탭 수 | 8개 | 5개 (+ 회원 선택 화면) |
| 성격 | 운영·관리·집계 | 내 수강권 사용과 요청 |

홈(`index.html`)의 진입 카드는 **정보 등록 → 사업자 대시보드 → 회원 포털 → Agent 페이지** 순이다.
회원 포털로 가는 길은 홈 카드 하나뿐이고, Agent 페이지는 포털로 이동하지 않는다.

```text
index.html
   ├─ 정보 등록          아카데미·수강생 만들기 (최초 1회)
   ├─ 사업자 대시보드     운영 전체
   ├─ 회원 포털          수강생 본인 화면
   └─ Agent 페이지       역할별 대화 화면(백엔드 미연동)
```

> **주의**: 지금은 로그인이 없다. 회원 포털은 URL의 `student_id` 로 대상을 정할 뿐 본인 확인을 하지 않고,
> 대시보드도 아카데미만 고르면 모든 데이터를 볼 수 있다. 실제 서비스로 쓰려면 인증·권한이 먼저 필요하다.

## 1. 사업자 화면 — `dashboard.html`

상단에서 아카데미를 고르면 8개 탭이 열린다. 탭은 처음 열 때만 데이터를 불러오고,
상태를 바꾸면 영향을 받는 탭만 다시 조회한다.

```text
[아카데미 선택]
 개요 | 오늘의 출결 | 미처리 예약 | 수강생 | 수강권 종류 | 관리 대상 | 문의 | 통계
```

### 1.1 개요 — 오늘과 이번 달을 한눈에

| 구역 | 제공 UI | 할 수 있는 일 |
|---|---|---|
| 수강 일정 달력 | 월간 달력(일~토), 날짜마다 예약·완료·취소 건수 배지, 오늘 칸에 `오늘` 배지 | 이전/다음 달 이동, 날짜 클릭 → 그날 일정 목록에서 **완료·취소·완료 취소·회원 상세** |
| 운영 현황 | 기간 프리셋(오늘·최근 7일·최근 30일·이번 달·지난달·사용자 지정) + KPI 12종 | 기간을 바꿔 신규 회원·발급·완료·취소 추이 확인 |

KPI 12종: 전체/활성 수강생, 신규 수강생, 수강권 발급, 수강 완료, 기간 내 예약·취소,
**미처리 예약**, 14일 이내 만료, 잔여 3회 이하, 사용 가능 수강권, 전체 잔여 횟수.

### 1.2 오늘의 출결 — 오늘 현장에서 쓰는 화면

오늘 예정된 수강을 시간순 표로 보여준다.
표시: 시간 · 수강생 · 수업명 · 수강권 · 잔여 · 만료일 · 상태.

| 기록 상태 | 버튼 |
|---|---|
| 예약(RESERVED) | 완료 · 취소 · 상세 |
| 체크인 중(CHECKED_IN) | 완료 · 상세 |
| 완료(COMPLETED) | 완료 취소 · 상세 |
| 취소(CANCELLED) | 상세 |

- **완료** 확인창에 `잔여 5회 → 4회` 처럼 변화를 미리 보여준다.
- **완료 취소(복구)** 는 사유 입력이 필수이며 잔여 1회를 되돌린다.
- 상단 `예약 만들기` 로 회원·수강권·수업명·일시를 골라 대신 예약할 수 있다.

### 1.3 미처리 예약 — 출결 확인이 필요한 지난 예약

예정 시각이 지났는데 아직 `RESERVED` 인 기록만 모아 보여준다.
현재 데이터로는 결석을 확정할 수 없어 **‘결석’이 아니라 ‘미처리·결석 의심’** 으로만 부른다.
각 행에서 완료 처리·예약 취소·회원 상세로 정리한다.

### 1.4 수강생 — 찾고, 고치고, 발급한다

- 검색: 이름 · 전화번호 · 이메일 · 활성/비활성 · 회원 만료일 범위, 정렬 6종, 페이지네이션
- 행의 `상세` → 드로어에서:
  - 기본 정보(연락처·메모·등록일·만료일·활성 여부)와 요약(전체 잔여, 최근 수강일, 다음 예약, 예약·완료·취소 건수)
  - **정보 수정**(이름·전화·이메일·메모)
  - **수강권 발급**(상품 선택 → 회차·유효기간·가격 미리보기 → 구매일·시작일 지정)
  - **예약 만들기**
  - 보유 수강권 목록과 최근 수강 기록

### 1.5 수강권 종류 — 판매 상품 관리

가로 카드 목록으로 상품을 관리한다. 카드에는 이름·설명·총 횟수·유효기간·가격·**1회 수업 시간(분)** 이 보인다.

- `+ 종류 추가` / 카드의 `수정` · `삭제`
- `◀ ▶` 로 노출 순서 변경(회원 포털의 상품 노출 순서에 그대로 반영)
- 삭제해도 **이미 발급된 수강권과 과거 기록은 발급 시점 이름·시간으로 그대로 남는다.**

### 1.6 관리 대상 — 먼저 연락할 회원 찾기

| 목록 | 조건 | 필터 |
|---|---|---|
| 만료 예정 수강권 | 잔여가 남은 채 곧 만료 | 7 / 14 / 30일 |
| 잔여 횟수 부족 | 만료 전 수강권의 잔여가 적음 | 0 / 1 / 3회 이하 |
| 만료됐지만 잔여 있음 | 이미 만료 + 잔여 1회 이상 | — |
| 재등록 후보 | 아래 4개 사유 중 하나 이상 | — |

재등록 후보 사유 배지: `잔여 부족` · `곧 만료` · `모두 소진` · `만료 · 최근 수강`.
한 회원은 한 번만 나오고 사유는 여러 개가 붙는다. 상담·연락 이력은 저장하지 않는다.

### 1.7 문의 — 회원 질문에 답한다

상태 칩(전체/답변 대기/답변 완료/종료)으로 거른 표에서 문의를 열면 드로어에 대화가 시간순으로 보인다.

- **답변 등록** → 문의 상태가 `답변 완료(ANSWERED)` 로 바뀐다.
- **문의 종료** → `종료(CLOSED)`. 이후에는 양쪽 모두 메시지를 추가할 수 없다.
- 회원이 연결한 수강권·예약이 있으면 잔여 횟수까지 함께 보여준다.

### 1.8 통계 — 기간 단위로 돌아보기

기간과 집계 단위(일/주/월)를 고르면 아래가 함께 갱신된다.

- **신규 등록**: 신규 회원 수, 직전 동일 기간 대비 증감·증감률, 구간별 막대
- **수강권 발급**: 발급 건수·총 회차·종류별 표, **발급가 기준 합계**(실제 매출이 아님)
- **수강 이용**: 예약·완료·취소·미처리, 구간별/수업명별/종류별 막대
- **장부 정합성 점검**: 저장된 잔여와 `총 횟수 + 차감 합계` 를 비교해 어긋난 수강권만 보여준다(조회 전용, 자동 수정 없음)

## 2. 수강생 화면 — `member.html`

### 2.0 회원 선택

홈 카드로 들어오면 아직 대상이 없으므로 **아카데미 → 회원** 선택 화면이 먼저 뜬다.
고르면 `member.html?academy_id=..&student_id=..` 로 다시 열리고, 이후에는 새로고침해도 같은 화면이 유지된다.
화면에도 "아직 로그인 기능이 없어 직접 선택합니다" 라고 적어 둔다.

```text
[아카데미 · 회원 이름]        [계정 다시 선택] [홈으로]
 홈 | 수강권 | 예약 | 출석·퇴실 | 문의
```

### 2.1 홈 — 내 상태와 지금 할 일

- KPI 5종: 전체 잔여 횟수 · 사용 가능한 수강권 · 가장 가까운 만료일 · 오늘 일정 · 답변 대기 문의
- **지금 할 일**
  - 수업 중(체크인 상태)이면 그 수업 카드와 `퇴실하기`
  - 다음 예약이 있으면 그 카드와 `출석하기` · `예약 취소`
  - 둘 다 없으면 "예약 탭에서 잡아 보세요" 안내
- 빠른 이동 버튼(수강권 구매 · 예약하기 · 출석·퇴실 · 문의하기)
- 최근 이용 내역 5건

### 2.2 수강권 — 사기와 지우기

**구매 가능한 수강권**: 상품 카드에 이름·설명·총 횟수·유효기간·**1회 수업 시간**·가격이 보인다.
`구매하기` 를 누르면 확인창이 뜬다.

```text
그룹 필라테스 10회권을 구매하시겠습니까?

10회
유효기간 90일
1회 수업 시간 50분
가격 350,000원

현재 버전에서는 별도 결제 없이 즉시 등록됩니다.
```

**내 수강권**: 잔여 막대와 함께 잔여/사용/총 횟수, 1회 수업 시간, 구매일·시작일·만료일, 상태 배지
(`사용 가능` · `소진` · `만료`)를 보여준다. 원본 상품이 지워진 수강권은 구매 당시 이름으로 표시하고
"원본 상품이 삭제된 수강권" 이라고 알려 준다.

`삭제` 는 경고 확인을 거친다.

```text
그룹 필라테스 10회권을 삭제하시겠습니까?

남은 횟수와 관계없이 수강권이 삭제됩니다.
기존 수강 기록은 유지됩니다.
```

### 2.3 예약 — 수업 잡기

예약 폼에서 **사용할 수강권 → 수업명 → 수업 시작 일시 → 메모** 를 입력한다.
수강권을 고르면 잔여 횟수·만료일·1회 수업 시간이 안내되고, 시작 일시를 고르면 **예상 종료 시각**이 표시된다.
(실제 저장되는 종료 시각은 서버가 수강권의 수업 시간으로 계산한다.)

**내 예약** 은 상태 칩(전체/예정/체크인 중/완료/취소)으로 거르며, 카드마다
수업명 · 시작~종료 · 수강권 · 잔여 · 체크인/퇴실 시각을 보여준다.

| 상태 | 버튼 |
|---|---|
| 예정 | 출석하기 · 예약 취소 |
| 체크인 중 | 퇴실하기 |
| 이용 완료 / 취소됨 | (표시만) |

예약을 잡아도 **횟수는 줄지 않는다.** 확인창에서도 그 점을 알려 준다.

### 2.4 출석·퇴실 — 수업 당일

아직 처리되지 않은 예약만 모아 보여주고, **수업 중(체크인)인 카드를 맨 위로** 올린다.

- `출석하기` → 확인창(예약 시간·예상 종료·"출석 시점에는 횟수가 차감되지 않습니다") → 체크인 시각 기록
- `퇴실하기` → 확인창("퇴실하면 수강이 완료되고 수강권 1회가 차감됩니다") → 완료 처리 + 1회 차감 + 남은 횟수 안내
- 처리 중에는 버튼이 잠겨 두 번 눌러도 두 번 차감되지 않는다.

### 2.5 문의 — 묻고 답 받기

작성 폼: **문의 유형**(수강권·예약·수강/출결·출석/퇴실·횟수 차감 오류·기간 연장·환불·시설·기타),
제목, 내용, 그리고 선택 사항인 **관련 수강권**·**관련 예약**.

목록에는 제목·상태 배지(`답변 대기`/`답변 완료`/`종료`)·유형·등록일·메시지 수·최근 메시지 시각이 보인다.
`자세히 보기` 를 누르면 드로어에서 대화가 말풍선으로 시간순 정렬돼 나오고,
**추가 메시지** 를 보내거나 **문의 종료** 를 할 수 있다. 종료된 문의는 입력이 막힌다.

## 3. 사용자 이용 흐름

### 3.1 사업자 최초 세팅 (한 번)

```text
정보 등록에서 아카데미 만들기
   → 정보 등록에서 수강생 등록
   → 대시보드 > 수강권 종류에서 판매할 상품 등록
        (총 횟수 · 유효기간 · 가격 · 1회 수업 시간)
   → 노출 순서를 ◀ ▶ 로 정리
```

이 단계가 끝나야 회원 포털의 ‘구매 가능한 수강권’에 상품이 보인다.

### 3.2 수강생 첫 이용

```text
홈 > 회원 포털
   → 아카데미·본인 선택
   → 수강권 탭에서 상품 확인 → 구매 (확인창 → 즉시 등록)
   → 홈에서 잔여 횟수·만료일 확인
   → 예약 탭에서 수강권·수업명·일시 선택 → 예약
        (예상 종료 시각 확인, 이 시점에는 차감 없음)
```

### 3.3 수강생 수업 당일

```text
출석·퇴실 탭
   → [출석하기]  상태: 예정 → 체크인 중, 체크인 시각 기록, 차감 없음
   → 수업 진행
   → [퇴실하기]  상태: 체크인 중 → 이용 완료, 퇴실·완료 시각 기록, 잔여 1회 차감
   → 홈/수강권 탭의 잔여 횟수가 즉시 갱신
```

취소가 필요하면 **체크인 전에** 예약 탭이나 홈에서 취소한다.
이미 체크인했다면 회원이 스스로 취소할 수 없고, 문의로 요청해야 한다.

### 3.4 사업자 하루 운영

```text
대시보드 > 개요
   → 달력에서 오늘 일정과 이번 달 흐름 확인, KPI로 미처리 건수 확인
   → 오늘의 출결 탭
        · 회원이 스스로 출석·퇴실했으면 상태만 확인
        · 직접 처리해야 하면 [완료] (예약 상태에서 바로 완료해도 됨)
        · 안 오면 [취소]
        · 잘못 눌렀으면 [완료 취소] + 사유 → 잔여 1회 복구
   → 미처리 예약 탭에서 지난 예약 정리
   → 문의 탭에서 답변
```

### 3.5 사업자 회원 관리·발급

```text
수강생 탭에서 검색 → [상세]
   → 정보 수정(연락처·메모)
   → 수강권 발급(현장 결제 후 등록하는 경우)
   → 대신 예약 만들기
   → 보유 수강권·최근 기록으로 상담
```

### 3.6 문의 왕복

```text
[회원] 문의 등록                     상태: 답변 대기(OPEN)
   → [사업자] 대시보드 > 문의 탭에서 답변    상태: 답변 완료(ANSWERED)
   → [회원] 문의 상세에서 답변 확인
        · 더 물어보면 추가 메시지        상태: 다시 답변 대기(OPEN)
        · 해결됐으면 문의 종료           상태: 종료(CLOSED)
   → 종료 후에는 양쪽 모두 메시지 추가 불가
```

사업자도 문의를 종료할 수 있다.

### 3.7 주간·월간 점검

```text
대시보드 > 관리 대상
   → 만료 예정 / 잔여 부족 / 만료+잔여 / 재등록 후보 확인 → 연락
대시보드 > 통계
   → 신규 등록 추이와 직전 기간 대비 증감
   → 종류별 발급 현황(발급가 기준 합계)
   → 수강 이용(완료·취소·미처리)
   → 장부 정합성 점검으로 잔여 횟수 어긋남 확인
```

## 4. 두 화면이 만나는 지점

한쪽에서 한 일이 다른 쪽 화면에 어떻게 나타나는지 정리한다.

| 누가 무엇을 하면 | 반대편에서 보이는 곳 |
|---|---|
| 사업자가 **수강권 종류 등록/순서 변경** | 회원 포털 ‘구매 가능한 수강권’ 목록과 순서 |
| 사업자가 **수강권 종류 삭제** | 이미 산 회원의 카드에 "원본 상품이 삭제된 수강권" 표시(이름·시간은 구매 시점 그대로) |
| 회원이 **수강권 구매** | 대시보드 KPI(수강권 발급), 통계(발급 건수·발급가 합계), 수강생 상세의 보유 수강권 |
| 회원이 **예약** | 대시보드 개요 달력, 오늘의 출결 표 |
| 회원이 **체크인** | 오늘의 출결·달력의 상태가 `체크인 중` 으로 바뀜(잔여는 아직 그대로) |
| 회원이 **퇴실** | 잔여 1회 차감 → KPI 수강 완료, 잔여 부족·만료 예정 목록, 통계 |
| 회원이 **출석하지 않음** | 예정 시각이 지나면 대시보드 ‘미처리 예약’ 탭에 쌓임 |
| 사업자가 **완료 처리** | 회원 포털의 해당 예약이 `이용 완료` 로 바뀌고 잔여가 줄어듦 |
| 사업자가 **완료 취소(복구)** | 회원 잔여 1회 복구, 그 기록은 `취소됨` 으로 표시 |
| 회원이 **수강권 삭제** | 수강 기록은 남고 연결만 끊김. 통계·기록에는 구매 시점 이름으로 계속 집계 |
| 회원이 **문의 등록/추가 메시지** | 대시보드 문의 탭 상태가 `답변 대기` |
| 사업자가 **답변** | 회원 포털 홈의 ‘답변 대기 문의’ 수와 문의 상세 |

## 5. 상태와 권한

### 5.1 수강 기록 상태

```text
        [예약 RESERVED] ──출석──> [체크인 중 CHECKED_IN] ──퇴실──> [이용 완료 COMPLETED]
              │                          │                              │
            취소                      완료(사업자)                   완료 취소(사업자)
              ↓                          ↓                              ↓
        [취소됨 CANCELLED]        [이용 완료 COMPLETED]           [취소됨 CANCELLED]
                                                                   (잔여 +1 복구)
```

| 동작 | 회원 | 사업자 | 잔여 횟수 |
|---|---|---|---|
| 예약 | O | O(대신 예약) | 변화 없음 |
| 출석(체크인) | O | — | 변화 없음 |
| 퇴실 | O | — | **−1** |
| 완료 처리 | — | O (예약·체크인 중 모두) | **−1** |
| 예약 취소 | O (예약 상태만) | O (예약 상태만) | 변화 없음 |
| 완료 취소(복구) | — | O (사유 필수) | **+1** |

체크인한 뒤에는 회원도 사업자도 일반 취소를 할 수 없다. 완료 처리한 뒤 되돌리려면 복구를 쓴다.

### 5.2 문의 상태

```text
[답변 대기 OPEN] ──사업자 답변──> [답변 완료 ANSWERED]
        ↑                                │
        └────── 회원 추가 메시지 ─────────┘
                     │
                  종료(회원 또는 사업자)
                     ↓
              [종료 CLOSED]  (메시지 추가 불가)
```

## 6. 두 화면이 하지 않는 일

이용 흐름을 설명할 때 오해하기 쉬운 부분을 정리한다.

- **결제가 없다.** ‘구매’는 결제 없이 수강권을 바로 등록하는 동작이고, ‘삭제’는 환불이 아니라 기록 삭제다.
  통계의 ‘발급가 기준 합계’ 도 매출이 아니다.
- **일정 중복을 막지 않는다.** 같은 회원이 같은 시간에 여러 번 예약할 수 있고, 정원·강사·강의실 개념이 없다.
- **체크인 시간 제한이 없다.** 예약 상태이기만 하면 예정일 전후 언제든 출석 처리가 된다.
- **결석을 확정하지 않는다.** 지난 예약은 ‘미처리·결석 의심’ 까지만 표현한다.
- **알림이 없다.** 문의 답변이나 만료 예정은 화면을 열어야 확인된다.
- **인증이 없다.** 회원 포털의 대상은 URL 값이며 본인 확인을 하지 않는다.
